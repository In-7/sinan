## 0. 一句话

**打开应用第一眼就知道点哪里**：主页唯一主操作是「捕获」，其余一切更小、更灰；整窗是 PC 桌面观感而非放大的手机页。

## 1. 为什么值得做（诚实评估）

本方案**不是**"现有界面全面错了"。收益集中在一点，其余是补齐与重排：

| 维度 | 判断 | 依据 |
|---|---|---|
| **捕获**（核心缺口） | 新方案**明显更好** | 当前主页第一眼是卡片墙（"浏览"），新建要靠 `Ctrl+N` / 命令面板，没有常驻捕获主操作。灵感半衰期以分钟计 → 这是笔记应用第一入口的真实缺口 |
| **找回**（卡片网格） | 现状**有效，只是降级** | 网格对"扫读最近改过什么"有效；新方案把它降为「全部」视图保留，不废除 |
| **笔记 / 画布** | 现状**自洽，不推翻** | 两种 `NoteKind` 是清晰的建模，与 AFFiNE 的"同篇模式切换"只是不同路线；本方案只纠正它**不该当视图**（见 §2-E） |
| **外壳**（rail / 状态栏） | **中等收益** | 左列自 HubNav 撤掉后是空洞；rail 填洞 + 提升可发现性，非颠覆性 |
| **搜索入口** | **收益取决于执行** | 现状页内搜索框常驻可见（可发现性高）；退役后若 OmniBar / 打字即捕获没做好（中文 IME、误触发），可发现性反而下降 → **本方案最大风险，见 §7** |

**结论**：为"捕获"这一件事做阶段 1，是值得且划算的；阶段 2-6 属补齐，**不应一次性承诺全套**，应视阶段 1 验收结果再定。

### §2-E 笔记 / 画布 的归类（本轮校正）

**问题**：`HomeView` 把两件不同的事混进一维 tab——

- 心流 / 全部 / 日历 / 收藏 = **投影**（同一池子的不同看法）
- 笔记 / 画布 = **类型**（把池子切成两半）

已核实 `kLowFreqViews = [HomeView.notes, HomeView.canvas]`（`home_hub.dart:105-107`），空态文案分别为「还没有笔记」/「还没有画布」（`:1611-1612`）——确认它们是**类型筛选**。

**项目上次已经解决过这个混淆**：被撤掉的 HubNav 的 `_SpaceSwitch`（笔记/画布 空间切换器）注释明确写着它是"空间过滤器"，只驱动切换器 + 内联列表过滤、**不切主区**，且与 `hubNavSelectionProvider` 刻意解耦。把它做成 `HomeView` 的两个值 = 把已理清的混淆请回来。

**已定（干净版）**：

1. `HomeView` 收敛为纯投影四值：`timeline`（心流）/ `all` / `calendar` / `favorites`；移除 `notes` / `canvas`。
2. 类型改为 `FilterMenuButton` 的一个「**形态**」facet：全部 / 笔记 / 画布，与排序、标签同级。
3. `homeItemsProvider` 参数 `(view, tag)` → `(view, tag, kind)`；`kLowFreqViews` 与三点溢出菜单随之退役。
   - 预期成本：`home_items_provider_test` / `home_hub_test` 相关用例同步。
   - （备选未采纳）保留 `notes/canvas` 在三点菜单不动、仅新增形态 facet——改动小但两个维度仍冗余。

**AFFiNE 式"同篇文档 ⇄ 画布切换"**：另立 spike，**不在本方案范围**（§6）。

## 5. 阶段 1 细化

### 5.1 OmniBar（新文件 `lib/src/app/omni_bar.dart`）

> ⚠️ **2026-10-08 修订**：捕获框**独立化**——不再"一框三用（捕获+搜索+命令）"。改为
> **常驻大输入框**（高 ~64，整宽，placeholder「记点什么…」），只做捕获：回车 →
> `runCaptureNote` 新建 spark。搜索**独立**走左栏「搜索」项 + `Ctrl+K` 浮层，命令走
> `Ctrl+Shift+P`。去掉检索下拉与 `#` 标签模式（保留 `/` 命令前缀作为进阶入口可选）。
> 详见末尾修订记录。

常驻 HomeHub 顶部，高 44；聚焦时全页压暗 ~60%（遮罩不拦截点击，点击即失焦），结果浮层带投影浮出。

| 输入 | 下拉 | Enter | 胶囊 |
|---|---|---|---|
| 空 | 无 | 不动作（防手滑） | 「记点什么…」灰 |
| 纯文本 q | 首行：标题完全匹配 →「打开已有」，否则「新建笔记「q」」；下方命中 ≤8 条（200ms 防抖，snippet 高亮复用 matchColor 口径） | 新建 spark：`createNote → saveTitle(q) → locate(focus: true)` | 「↵ 新建笔记」 |
| `/` 前缀 | 命令列表（`commandRegistryProvider` × `activeCommandScopesProvider` 作用域过滤） | 执行命令 | 「↵ 执行命令」 |
| `#` 前缀 | 标签（快照内存聚合） | 走 `homeItemsProvider((view, tag))` 现有路径 | 「↵ 按标签筛选」 |
| Shift+Enter / ↓选中后 Enter | — | `selectHome(all) + searchNotifierProvider.submit(q)`（与 `search_palette.dart:260-275` 同口径） | 「↵ 查看全部结果」 |

**误建防护**（自 `ne2w.md` 吸收，`capture_first` 漏了）：标题完全匹配时首行改「打开已有」；新建后可 `⌘Z` / undo_toast 撤销。

**三条硬约束**：
1. 创建**必须**走 `runCreateNote`（`commands.dart:196`）同一管线，只多传初始文本——不写第二套创建逻辑。
2. 检索**只**调 `contentRetrieverProvider`（app 层唯一检索端口）。
3. 事件遵守 `bindings.dart` 旁观者约定，OmniBar 持焦时不碰全局分发。

### 5.2 打字即捕获 + 中文 IME

三重闸：`selectedId == null` ＋ 无模态浮层 ＋ OmniBar 未持焦。已核实 `home_hub` 现有 5 处 `FocusNode` 不消费字符键。

**中文 IME 取舍**（自 `ne2w.md` 吸收，必做否则中文直接翻车）：
- ① 隐藏可聚焦 `TextField` 再同步文本 —— 多一个同步通道就多一处拼音/候选竞态；
- ② **OmniBar 在主页默认持焦、视觉上去掉焦点框**（**推荐**）—— 最少通道、天然贴合"打字即捕获"；① 作为 ② 实测出问题时的退路。
- 中文标点、空格、回车统一走 IME 提交事件。

### 5.3 心流流（新文件 `lib/src/app/stream_view.dart`）

- `HomeView` 追加 `timeline('心流')`；同步 `icon()` 扩展、tab 行、**`navHistoryProvider` 默认视图改 `timeline`**。tab 行 = **心流 | 全部 | 日历 | 收藏**（心流首位）。
- 分组：今天 / 昨天 / 本周 / 本月 / 更早，键 = `revisedAt`（与 `allNotes` 的 `revised_at DESC` 同源）；收藏**不**置顶（纯度，收藏走 favorites 视图）；「更早」>200 条折叠为计数行懒展开。
- 行 `_StreamTile` 高 44 两行：标题（13px/medium，无标题借正文首行，空白显示「（空白）」）＋ 元数据（11px 灰：标签 · 相对时间）；画布类带 `CustomIcons.canvas` 角标，不画缩略图。
- 交互：hover 微底 + 行尾浮出「收藏 / 更多」；点击 `locate(noteId)` **不带 focus**；↑↓ 移 `FocusRing`，Enter 打开。
- 数据：`notesProvider` 快照内存分组，无新 SQL（万篇 ~100ms 已有实测）。

### 5.4 页内搜索框退役

删除 `home_hub.dart:463-536` 的 `TextField` 段与 `_searchFocus`（`:281/303`）；`FilterMenuButton` / 排序钮保留。`searchNotifierProvider`、`_SearchResultsView`、搜索态切 tab 不清词等语义**全部保留**，只换唯一写入口为 OmniBar。

## 6. 不做清单

- 不换 material_ui 内核、不引入新 UI 三方包。
- 不动 vendored appflowy 内核（皮肤除外，阶段 6）。
- 不做 Mica / 亚克力窗口材质（2026-09-22 已取消）。
- **不做 AFFiNE 式"同篇文档 ⇄ 画布"模式切换** → 另立 spike：数据层 `moveBlockToCanvas` / `moveBlockToDocument` 已有基础（画布→文档已完成，文档→画布未做完），但往返投影未完整验证。属"发展"能力，不混进阶段 1。
- 不做 `?` 前缀问 AI / 意图胶囊 Tab 切换（`ne2w.md` §9.4）——AI 已有安静入口，塞进来只会让阶段 1 膨胀。
- 移动端分支不动（2026-09-18 拍板只做桌面）。
- `raw primary` 多处前景用法：遗留观察点，另议。

## 7. 验收与风险

- **基线**：双 analyze + `flutter test` 全绿。⚠️ 方案原文写的"1027+"与实测不符，**今日全量实测 952 passed**，以 952 为准。
- **性能红线**：分组/聚合只能是内存 O(n)；OmniBar 防抖 200ms；主页首帧不引入新同步重活。
- **主要风险**：
  - **搜索可发现性回退**（最大）：页内框退役后若 OmniBar / 打字即捕获不力，用户找不到搜索 → 验收必须手测"不知道 Ctrl+K 的用户能否找到搜索"。
  - 中文 IME 必须实机验证，不能只靠 `onKeyEvent`。
  - 打字即捕获误触发：三重闸要覆盖 AI 浮层 / 命令面板 / 设置面板打开时。
  - 默认视图改动牵动 `title_bar_nav_test` / `home_hub_test`（预期成本）。
  - `home_hub.dart` 体积已大 → 新组件一律独立文件。

## 8. 修订记录（2026-10-08）

用户推翻原方案两处，定稿如下，已开工：

### 8.1 撤销决策 B → 可折叠左导航栏

- **形态**：单列两态，复用既有 `navCollapsedProvider`（已存在，`providers.dart:141`）。
  - 折叠：56px 纯图标轨（类似 VS Code 收起态）。
  - 展开：248px 图标 + 文字导航列表（宽度可 `Splitter` 拖拽记忆 220–320）。
  - 动画：`AnimatedContainer(width)`，文字 `AnimatedCrossFade` 淡入淡出（不靠布局位移，避免文字横跳）。
  - 默认态：**展开**（第一眼能看见有什么）。
- **内容（空间轴：去哪）**：
  - 上组：主页 / 心流 / 全部 / 日历 / 收藏 / **搜索（独立入口）**。
  - 底组（钉底）：设置 / AI 问答（开关态点亮）。
  - **历史 `← →` 留在 `WindowStrip` 左簇**（决策 D 不变：顶条=时间轴，导航栏=空间轴）。
- **折叠机制**：`Ctrl+\` 接上（原 `ui_rewrite_plan.md` §3.4 已登记，此前卡在"侧栏不可折叠"）；折叠钮放在导航栏自身头部/底部。
- **与标题栏协调**：`WindowStrip` 左簇回归本职——只留 `← →` 历史（折叠钮在导航栏内）；右簇的 设置/AI 迁进左栏底组。
- **落地步骤**：a. 新建 `nav_rail.dart`；b. `home_screen.dart` 加左列 + `WindowStrip` 左簇只留历史；c. 捕获框独立大输入框（替换 OmniBar）；d. 宽度拖拽记忆 + 状态恢复 + 回归测试。

### 8.2 捕获框独立化（不与搜索混）

- 撤销 OmniBar「一框三用」：主页顶部改为**独立常驻大输入框**（高 ~64，整宽，placeholder「记点什么…」），直接可输入，回车 → `runCaptureNote` 新建 spark（带初始文本）。
- **不与搜索混**：搜索走左栏「搜索」项 + `Ctrl+K` 全局浮层；命令走 `Ctrl+Shift+P`。
- 删掉"打字即捕获默认持焦去焦点框"那套伪装（框常驻可见，无需默认持焦）；三重闸简化为"主页分支且未持焦"。
- 位置明显大于原 44px 行内框，符合"大一些、直接可输入"。
